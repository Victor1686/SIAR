# SIAR - Arquitectura del Sistema

## 1. Arquitectura general

SIAR (Sistema Integral de Administración para Restaurantes) se organiza mediante una arquitectura en capas. Su objetivo es separar la interfaz de usuario, la lógica de negocio, el acceso a datos y la configuración técnica para facilitar el mantenimiento y la evolución del sistema.

## 2. Capa de presentación: `src/presentation/`

Esta capa contiene los archivos que permiten al usuario interactuar con el sistema mediante la interfaz web.

Contenido actual:
- `index.html`: página principal.
- `menu.html`: interfaz del menú.
- `admin-menu.html`: interfaz de administración del menú.
- `estilos.css`: estilos visuales.
- `script.js`: comportamiento de la interfaz.
- `menu-data.js`: manejo de los datos del menú en la interfaz.

## 3. Capa de lógica de negocio: `src/business/`

Esta capa estará destinada a implementar las reglas de negocio y los procesos funcionales de SIAR.

Su responsabilidad será validar las operaciones del sistema y coordinar los procesos entre la presentación y el acceso a datos.

La implementación de esta capa debe verificarse en el código antes de considerarla terminada.

## 4. Capa de acceso a datos: `src/data/`

Esta capa se encarga de la comunicación con la base de datos y de las operaciones necesarias para consultar o guardar información.

Archivo identificado:
- `conexion.js`: contiene la configuración o lógica de conexión a la base de datos, cuyo funcionamiento debe comprobarse.

El archivo SQL de la base de datos se encuentra en `database/siar_db.sql`.

## 5. Configuración e infraestructura: `src/config/`

Esta carpeta reúne archivos relacionados con la configuración técnica del sistema.

Archivos identificados:
- `env.js`: relacionado con la configuración de variables de entorno.
- `script.js`: su responsabilidad debe confirmarse revisando su contenido.

## 6. Organización del proyecto

La estructura del repositorio separa la interfaz web, la conexión a datos, la configuración y los archivos de base de datos. La lógica de negocio y los demás componentes del backend deben implementarse o verificarse de acuerdo con el estado real del código.

## 7. Mantenimiento

La documentación debe mantenerse actualizada conforme avance el desarrollo. Antes de registrar una funcionalidad como terminada, se debe comprobar su implementación y funcionamiento.
